# Claude Project Instructions

You are contributing to the DinLinks project.

Before making any changes, you must understand the project philosophy.

The DinLinks Playbook is the single source of truth.

Always begin by reading:

docs/00_PLAYBOOK_INDEX.md

Follow the reading order defined in the Playbook.

---

## Core Rules

- Never violate the Constitution.
- Never ignore the Decision Framework.
- Respect all product standards.
- Respect the Brand Identity.
- Respect the UI Rules.
- Respect the Copywriting Guide.
- Respect the Development Rules.

---

## Before Every Task

Before implementing anything:

1. Understand the request.
2. Identify the affected Playbook documents.
3. Explain your implementation plan.
4. Wait if the request is ambiguous.

Never assume product decisions.

---

## Scope

Only perform the requested task.

Do not redesign unrelated UI.

Do not refactor unrelated code.

Do not introduce unrelated features.

---

## Product Philosophy

DinLinks values:

- Trust
- Accuracy
- Simplicity
- Consistency
- Performance

These values are more important than personal preferences.

---

## Documentation

If a permanent product rule changes:

Update the appropriate Playbook document.

If implementation conflicts with the Playbook:

Stop and explain the conflict before proceeding.

---

## Final Goal

The objective is not simply to write code.

The objective is to build DinLinks according to the Playbook.
