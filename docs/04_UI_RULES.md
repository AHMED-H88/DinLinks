# DinLinks UI Rules

## Purpose

This document defines the UI standards for every screen in DinLinks.

Every component must follow these rules.

---

# Overall Philosophy

The interface should feel:

- Clean
- Calm
- Premium
- Fast
- Spacious
- Consistent

Never feel:

- Busy
- Colorful
- AI-inspired
- Experimental

---

# Visual Hierarchy

Every screen should have a clear visual hierarchy.

Users should immediately understand:

- What is most important.
- What is secondary.
- What action should be taken next.

The interface should guide attention naturally.

Never force users to search for the primary action.

---

# Layout

Always use generous whitespace.

Never overcrowd a page.

Every section must have a clear purpose.

---

# Cards

Cards should:

- Have a clear hierarchy.
- Be easy to scan.
- Use subtle borders.
- Avoid heavy shadows.

---

# Buttons

Only one primary button per section.

Primary buttons should represent the main action.

Secondary actions should never compete visually.

---

# Forms

Keep forms short.

Group related fields.

Use clear labels.

Show validation messages close to the field.

---

# Search

Search is the core of DinLinks.

Search must always be:

- Visible
- Fast
- Easy to use

Never hide search behind unnecessary clicks.

---

# Icons

Use one icon style across the entire product.

Icons support text.

Icons should never replace clear labels.

---

# Colors

Color communicates meaning.

Never use color only for decoration.

Use semantic colors consistently.

Primary:
- Rich Black / Charcoal

Background:
- White
- Off-white

Secondary:
- Neutral Gray

Allowed accent colors:
- Green → verification / success
- Red → errors
- Yellow → warnings

Blue is not part of the DinLinks brand identity.
Use blue only when required by third-party integrations or platform-specific conventions.

---
# Typography

Typography is one of DinLinks' strengths.

Never replace the current font unless explicitly requested.

Prioritize:

- clean
- modern
- readable

---

# Animations

Animations should remain subtle.

Good:
- hover transitions
- smooth opacity
- soft scaling
- elegant motion

Avoid:

- bouncing
- flashy effects
- exaggerated animations

---

# User Feedback

Every user action should receive clear feedback.

Examples:

- Loading
- Success
- Error
- Empty state

Users should never wonder if the system is working.

---

# Spacing

Spacing creates quality.

When unsure:

Choose more whitespace.

---

# Responsive Design

Mobile first.

Every screen must work perfectly on:

- Mobile
- Tablet
- Desktop

---

# Accessibility

Maintain strong contrast.

Large click targets.

Keyboard accessible.

Readable typography.

---

# UI Consistency

The same action should always look and behave the same throughout the product.

Buttons

Cards

Forms

Navigation

Status indicators

should remain visually consistent across every page.

---

# Key Principle

Consistency is more important than creativity.

Users should always feel that every page belongs to the same product.
